# 네이버 블로그 크롤러 클라우드 V1.2 업데이트 안내

2026-10-15 업데이트: V1.1에서 확인된 30건 수집 정지 현상 개선을 위한 **화면 탐색 및 진단 기능 업데이트**.

## 변경 내용
- 키워드별 최대 수집 건수 **300건** 지원 (10, 20, 50, 100, 200, 300건).
- 최대 스크롤 횟수 **80회** 지원.
- 사용자가 실제 브라우저에서 볼 수 있는 명시적 '다음 페이지' / '더보기' 버튼을 탐색하고, 게시글이 추가로 나타난 경우에만 다음 페이지 이동으로 인정.
- 새 게시글 3회 연속 미발견 시 무조건 종료하는 기존 로직 개선. 하단 스크롤과 페이지 탐색 검증을 병행.
- 화면 결과가 요청 건수보다 적으면 수집 종료 원인과 실제 수집 건수를 로그에 기록.
- 엑셀 **키워드별 현황**에 `종료 사유`, `페이지 이동 횟수` 항목 추가.
- 웹 결과 표에 전체 수집 결과(최대 8키워드 x 300건)가 표시될 수 있도록 처리.
- V1.1 접근코드 기억, 블로그명 수집, 엑셀 다운로드 유지.

## 한계
- 300건은 **수집 상한**이지 검색 화면에서 게시글 300개가 표시된다는 보장은 아닙니다.
- API, 숨겨진 네이버 내부 검색 응답, 임의로 작성한 검색 파라미터 기반 페이지 요청은 사용하지 않습니다. 실제 브라우저에 렌더링된 게시글만 저장합니다.
- 네이버가 보여주는 추가 페이지, 사이트 구조, 접속 제한, 키워드 검색 결과 유무에 따라 수집 건수는 다를 수 있습니다.
- 수집 순서가 네이버 앱의 절대 순위와 동일하다고 보장하지 않습니다.
- 사이트 접근 제한이나 캡차를 우회하지 않습니다.

## GitHub 배포법 (이 업데이트 패키지)
1. ZIP을 압축 해제합니다.
2. **`naver_blog_cloud_v1_deploy` 폴더를 그대로** GitHub 저장소 루트에 업로드해 기존 같은 경로의 파일을 업데이트합니다.
3. 경로가 `naver_blog_cloud_v1_deploy/screen_crawler.py`와 `naver_blog_cloud_v1_deploy/static/index.html`처럼 유지되는지 확인합니다.
4. Commit changes 후 Railway 최신 커밋으로 빌드 및 배포되는지 확인합니다.
5. 서버가 Online 및 health 200 상태인 것을 확인합니다.
6. 모바일 웹, 키워드 1개, 100건, 최대 스크롤 35회, 스크롤 대기 2초, 스크린샷 저장 체크로 우선 테스트합니다.
7. 수집 후 실행 로그에서 종료 이유, 엑셀의 키워드별 현황에서 종료 사유와 페이지 이동 횟수를 확인합니다.

## 검증 방법
```bash
python -m pip install -r requirements.txt pytest httpx
python -m playwright install chromium
python -m pytest -q tests/test_cloud.py
```
- 실제 Chromium에서 구성한 모의 검색페이지에서 30건 + 30건 + 30건 + 5건으로 나뉜 **총 95건** 수집 시험.
- 최댓값 300건/스크롤 80회 요청 검증.
- 기존 FastAPI 인증, 상태, 다운로드 회귀 검증.
- 실제 네이버 운영 서버의 화면에서 **100건 이상 수집 성공 여부는 별도 확인 필요**.
